# Implementation decisions

Choices made while implementing `project_main_documentation.md` (rev. 6), where the doc left room
or the current libraries required a deviation. Add new entries at the bottom.

| ID | Decision | Why |
| --- | --- | --- |
| D-01 | Two extra packages: `device_bridge` (Android plugin) and `app_shell` (shared app composition). | `canUseFullScreenIntent`, channel state, safe restart and APK install are not exposed by any plugin. Both apps share 90% of the root wiring; duplicating it would double maintenance. |
| D-02 | `TaskSessionBloc` and `AvailabilityBloc` are Blocs, other state holders are Cubits. | `bloc_concurrency.droppable()` only applies to Bloc events (doc 7.4). |
| D-03 | FCM uses the registration-token API (`getToken`/`deleteToken`, deprecated in firebase_messaging 17). | The agreed contract sends `fcm_token`. The new FID API (`register()`/`onRegistered`) needs the backend to send by installation ID. Migrate together with the backend. |
| D-04 | Dev flavor without `API_BASE_URL` uses an in-memory fake backend; it is refused in staging/prod. | Lets the app run end to end without a backend; used by tests. |
| D-05 | Firebase is optional at runtime (`FirebaseStatus`). Gradle uses `missingGoogleServicesStrategy = WARN`; the Crashlytics Gradle plugin is applied only when every flavor has its config. | A fresh checkout must build. Production must provide the files (see SETUP.md). |
| D-06 | Certificate pinning in Dart (SPKI SHA-256), not in `network_security_config`. | Covers the Dart HTTP stack, including the background receipt. Prod release fails fast with fewer than two pins. |
| D-07 | Sign-in title/subtitle in Indonesian ("Selamat Datang Kembali"). | Doc A.1: all UI copy Indonesian; English design copy pending designer decision. Change in the ARB. |
| D-08 | Local countdown expiry first asks `GET /tasks/current` before showing Waktu Habis. | The server owns the clock; the user may have accepted on another device at the last second. |
| D-09 | Watch home pins the main action at the bottom; while In Progress it shows **Selesai** and the blocked reason instead of a disabled Check Out. | At 320x240 dp two 64 dp buttons plus content do not fit; Check Out is unusable during a job anyway (rule 6). |
| D-10 | Watch header icon buttons are 48 dp; Terima, Tolak and main buttons stay at 64 dp. | Doc 15 requires 64 dp for the main actions; 48 dp is the Material minimum and keeps room for content. |
| D-11 | Startup drop of an expired session is local only (no server calls). | The server already revoked it at the cutoff; network timeouts must not block the first screen. |
| D-12 | Soft update prompt "once per shift" = once per Jakarta calendar day. | Day shifts; works even when phones never log out. |
| D-13 | Golden tests use alchemist CI goldens only (text as blocks). | Identical results on Windows dev machines and Linux CI. |
| D-14 | Generated code (`*.g.dart`, `*.freezed.dart`, `*.config.dart`, `*.module.dart`, l10n) is committed; CI fails if it is stale. | Builds and reviews do not depend on running codegen first. |
| D-15 | Foreground alert is vibration only (looping pattern, faster in the last 10 s); sound comes from the background notification channel. | Doc 10.1 makes vibration primary and the stack has no audio package. Add a sound player if field tests show the need. |
| D-16 | The doc's example date `Sen, 27 Okt 2026` has the wrong weekday (27 Oct 2026 is a Tuesday). Tests use correct dates. | Sample data in the design mock. |
| D-17 | Presentation code is grouped per area: `presentation/<area>/{bloc,cubit,view,widgets}/`, events and states are `part of` their bloc/cubit, one public class per file. | Predictable file locations (bloc library's recommended layout); `part of` keeps private events working and gives one freezed file per bloc. |
| D-18 | Background readiness check (watch Home on start, every resume on all devices) only raises **blocking** non-network failures, never offers "Tetap Check In" and never checks in. Network is left to the offline banner; warnings are shown only on a Check In tap. | Doc 12 asks for checks at start and resume, but a sheet on every offline resume or for a battery warning is noise; a silent broken setup (notifications off, muted channel, wrong clock) is the real risk. |
| D-19 | Refused queued actions (outbox `conflict`): Selesai shows "Penugasan sudah ditutup atau dialihkan" and reconciles via `GET /tasks/current`; Check Out shows "Check Out ditolak server" and reloads availability. | Doc 16: "show a message and reconcile from the server". |
| D-20 | Shift end is a version-check point: `ShiftEndCubit.onShiftEnd` runs `AppGateCubit.check()` once per cutoff, after check-out/logout and before a Shorebird restart. Tapping an In Progress history item returns to Home (where its Selesai is), no separate detail screen. | Doc 13.1 lists shift end as a check moment. A detail screen would duplicate Home and need session data `feature_task` cannot depend on. |
| D-21 | The real backend (docs/technician-app-implementation-guide (1).md) delivers work orders over a Socket.IO socket (`/technician`) with no push. FCM is **kept** because the delivery channel is still being discussed with the backend: both channels feed one parser (`RealtimeEvent`, FCM data `{event, payload}` = the socket event) and one `TaskEventProcessor`, so a work order received twice is shown once. Remote setting `task_delivery` = `socket` (default) / `fcm` / `both` decides which run (socket + keep-alive foreground service, FCM token registration to the proposed `POST /devices/fcm-token`) and which readiness item blocks. | Supersedes doc 9.1 "FCM-first, no foreground service". Switching channels needs no app release. |
| D-22 | No Selesai. The backend has no complete call: a job stays In Progress until `work-order:updated COMPLETED` (or the snapshot no longer has it). The technician can only "Batalkan Penugasan" (backend cancel, checks them out). Only Check Out is queueable offline. | Backend guide part 1 step 6. |
| D-23 | Remote configuration is layered: Firebase Remote Config, then the Firestore document `app_config/<env>` (same field names, works on the Spark plan and offline from its cache), then compiled-in defaults. Feature flags, the version gate (`<app>_min_version`, …), `shift_schedule`, `shift_end_grace_minutes` and `task_delivery` all read through `RemoteSettings`. There is no `/app/config` endpoint. | The client may not upgrade to Blaze; the app keeps working on either. |
| D-24 | Shift end is decided by the app (the backend has no shift timer): `shift_schedule` (Asia/Jakarta, e.g. `{"S1":{"start":"07:00","end":"15:00"}}`) and the technician's `shift` from login give the cutoff, capped by the token expiry (12 h on the watch). The watch unpairs (`POST /technicians/me/unpair`) at the cutoff. The default schedule (07-15, 15-23, 23-07) is a placeholder until the backend serves it. | Backend guide part 2 step 7. |
| D-25 | The watch may use the camera (scanning the admin's enrollment QR; future features). Camera scanning lives in `packages/camera_scanner`, used by the apps only; feature packages receive a scan callback. The WD1 II hardware scanner (Newland broadcast) is also read, and the code can be typed. | User decision; replaces "the watch never depends on camera packages". |
| D-26 | Watch identity: EC P-256 key in the Android Keystore (`device_bridge`), one-time enrollment, every request and socket handshake signed; a `401` with `X-Server-Time` corrects the clock and retries once with a new nonce. A refused signature on the QR screen offers re-enrollment. | Backend guide part 2. |
